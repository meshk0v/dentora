# DENTORA — демо-сайт премиальной стоматологии

Демонстрационный сайт стоматологической клиники: каталог услуг и цен, врачи, онлайн-запись в 7 шагов и демо-панель администратора. Работает полностью статически на GitHub Pages, без сервера.

> ⚠️ Все данные демонстрационные: клиника, врачи, цены, сроки, адрес и телефон вымышлены. Фото — стоковые (Unsplash). Тексты не являются медицинской рекомендацией.

## Возможности

- **Главная** — hero, популярные услуги, команда, преимущества, этапы первого визита, галерея с лайтбоксом, FAQ, контакты, финальный CTA.
- **Услуги** (`#/services`) — поиск, фильтр по 8 категориям (синхронизирован с URL), переключение «каталог / прайс-лист», отдельная страница каждой услуги.
- **Врачи** (`#/doctors`) — поиск по имени, фильтр по специализации, профиль в модальном окне (ссылка на профиль: `#/doctors?profile=<id>`).
- **Онлайн-запись** (`#/booking`) — услуга → врач (или «любой») → дата → время → контакты → проверка → подтверждение. Валидация, маска телефона, защита от двойной отправки, выгрузка в календарь (.ics). Можно открыть с предвыбором: `#/booking?service=implant&doctor=mark-soloviev`.
- **Админ-панель** (`#/admin`) — счётчики по статусам, поиск, фильтры по дате и статусу, карточка записи, смена статуса, удаление с подтверждением, тестовые данные и сброс.

Записи хранятся **только в localStorage браузера** и никуда не отправляются. Админ-панель — прототип **без серверной авторизации**: не используйте её для реальных данных пациентов.

## Стек

React 18 · TypeScript · Vite 5 · Tailwind CSS 3 · React Router 6 (HashRouter) · Lucide React. Анимации — CSS + IntersectionObserver (без Framer Motion), учитывается `prefers-reduced-motion`.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173/dentora/
npm run build      # сборка в dist/
npm run preview    # просмотр сборки: http://localhost:4173/dentora/
```

Нужен Node.js 18+.

## Публикация на GitHub Pages

1. Создайте репозиторий (например, `dentora`) и запушьте код в ветку `main`.
2. В репозитории: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Каждый push в `main` запускает `.github/workflows/deploy.yml`: сборка и деплой.
4. Сайт будет доступен по адресу `https://USERNAME.github.io/dentora/`.

Базовый путь в workflow берётся из имени репозитория (`BASE_PATH=/<repo>/`), поэтому репозиторий можно назвать как угодно. Локально по умолчанию используется `/dentora/` (см. `vite.config.ts`). Для собственного домена соберите с `BASE_PATH=/`.

Маршрутизация через `HashRouter` (`/dentora/#/doctors`), поэтому обновление любой вложенной страницы не даёт 404.

## Адаптация под реальную клинику

Весь контент — в типизированных файлах `src/data/`:

| Файл | Что менять |
| --- | --- |
| `clinic.ts` | название, логотип (текст), телефон, почта, адрес, часы работы, шаг слотов, горизонт записи, `isDemo` |
| `services.ts` | категории, услуги, описания, этапы, длительность, цены |
| `doctors.ts` | врачи, фото, специализации, направления, рабочие дни |
| `faq.ts` | вопросы и ответы |
| `gallery.ts` | фотографии интерьера |

Изображения лежат в `public/images/` (WebP) и указываются по имени без расширения. Значок логотипа — `src/components/ui/Logo.tsx`, favicon — `public/favicon.svg`. Цвета и шрифты — `tailwind.config.js`.

Для реальной записи пациентов нужен сервер или CRM: замените `src/lib/storage.ts` вызовами API, а расписание в `src/lib/schedule.ts` — реальной доступностью врачей. В `index.html` стоит `noindex`, чтобы демо не индексировалось; уберите его перед запуском.

## Структура

```
src/
  components/   ui/ (Button, Field, Modal, Toast, Accordion…), layout/ (Header, Footer…)
  layouts/      MainLayout, AdminLayout
  pages/        страницы маршрутов
  features/     home/, services/, doctors/, appointments/, admin/
  data/         конфигурация контента
  hooks/        useAppointments, useReveal, useDocumentTitle
  lib/          storage, schedule, format, phone, validation
  types/        типы домена
  styles/       index.css
```
